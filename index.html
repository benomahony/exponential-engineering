the big idea

When you find a mistake, don't fix it.
Fix every future version of it.

"What deterministic rule would have caught this automatically?"

Write it as a lint rule, not a line in RULES.md. Run it everywhere.

the enforcement ladder

Not all "rules" are equal. Climb as high as you can.

  1. unrepresentable types make it impossible
  2. type checker fails the build
  3. lint rule fails with a fix hint
  4. test catches it after the fact
  5. review comment catches it sometimes
  6. AGENTS.md, RULES.md prose: a polite wish

Prose in a prompt is a suggestion. A failing check is a fact.

everything on. zero warnings.

NASA's Power of 10, rule 10: every warning on at the most pedantic setting, static analysers every day, and ship with zero warnings.

the NASA wayevery rule on, strictest mode, warnings and infos fail the build

A warning you tolerate is a rule you taught the agent to ignore.

actionable errors are just in time prompts

AGENTS.mdloaded every session, all of it, relevant or not. Burns context. Easy to skim past.
an actionable errorappears only when the mistake happens, on the exact line, with the exact fix.

Don't front load the context.
Deliver it the moment it's needed.

A lint rule that never fires costs zero tokens. One that fires is the most relevant prompt the agent will see all day.

anatomy of a good rule

The error message is the prompt. The agent reads it and fixes itself.

error: forbidden call

😐 the agent guesses

error: datetime.now() reads the wall clock.
  Use clock.now() so tests can
  freeze time.
  See docs/time.md

😎 the agent knows

  • says what is wrong
  • says what to do instead
  • points where to read more
  • is deterministic: same input, same answer

real rules, real cheap

Point agents at the right API with ruff:

[tool.ruff.lint.flake8-tidy-imports.banned-api]
"datetime.datetime.now".msg = "Use clock.now() so tests can freeze time."

Ban a pattern with ast-grep:

id: no-print-in-lib
language: python
rule:
  pattern: print($$$ARGS)
message: Use the logger from app.log, not print().
severity: error

Most mistakes are already a rule someone wrote. Turn it on before you write your own.

quality ratchets

Pick a number. Commit it. CI fails if it gets worse and tightens when it gets better.

lint violations, only ever down
lint violations
mon  412
tue  398  ✓ ratchet tightened
wed  401  ✗ CI fails: 401 > 398
thu  371  ✓ ratchet tightened

No big bang cleanup. Turn the rule on today, freeze the old violations, block every new one.

overwatch

The fastest loop is the one nobody has to start. Run your tests and linters in watch mode, right beside the agent.

  • full suite runs first, so you start green
  • every save reruns what changed
  • failures go straight back to the agent, before it moves on
  • runs zanity beside your tests
  • the turn can't end while the build is red

careful now

  • noisy rules are bugs. A false positive teaches agents (and humans) to add noqa everywhere.
  • prune. Hundreds of prose rules make agents follow fewer of them. Lint rules only speak when broken, so they scale. Prose doesn't.
  • escape hatches need reasons. # noqa: BLE001 retry loop logs it
  • don't make an LLM your linter. Pass or fail, every time, for free.

try it monday

  • turn every linter and type checker to its strictest setting
  • keep a "that again?!" list for one week
  • for each entry, find an existing lint rule
  • no rule exists? write one with ast-grep or semgrep
  • run tests and lint in watch mode with overwatch
  • make CI fail on it, and ratchet the count down
  • delete the matching line from AGENTS.md 🎉
