how to make every mistake
the last of its kind

the treadmill

Your agent writes a bug. You spot it. You say "please don't do that". It fixes it.

I swallowed an exception with a bare except: pass
fixed! ✨

Next week, a different session, a different file:

I swallowed an exception with a bare except: pass

You fixed the instance.
The category is still alive.

Agents don't remember last Tuesday. Your codebase does.

the big idea

When you find a mistake, don't fix it.
Fix every future version of it.

Ask one question:

"What rule would have caught this automatically?"

Then write that rule. Lint it. Run it everywhere.

It's kaizen for codebases that are written by robots. Yes, Toyota did this in the 1950s. We have more YAML. Toyota called it poka yoke: mistake proofing. Make the wrong thing impossible, or at least loud.

the loop

  1. spot a mistake in a diff, a review, an incident
  2. name the category, not the line
  3. encode it as a deterministic check
  4. run it in the LSP, the watcher, the CI
  5. let the agent self correct from the error message

↺ forever

Each lap is small. Five minutes. One rule. The point is that you never run the same lap twice.

why exponential?

A fix touches one line.

A rule touches every line written by every agent in every session, forever.

Rules compound like interest. Your agents get better without getting smarter, because the space of wrong answers keeps shrinking.

it cuts both ways

Agents copy what they see. Every pattern in your repo is a template for the next thousand lines.

One sloppy except: pass becomes ten. Ten becomes the house style. The agent isn't wrong, it's consistent.

No rules isn't standing still.
It's compounding the other way.

harden the codebase, not the agent

Agents come and go. Claude Code today, Codex tomorrow, something new next quarter.

tied to one agentprompts, skills, memory, clever system messages
lives in the repolint config, types, tests, CI, watchers

The repo is the shared context. Every agent and every human reads it, every session, no setup required.

Tune the agent and you improve one tool. Harden the codebase and you improve all of them, including the ones that don't exist yet.

the enforcement ladder

Not all "rules" are equal. Climb as high as you can.

  1. unrepresentable types make it impossible
  2. type checker fails the build
  3. lint rule fails with a fix hint
  4. test catches it after the fact
  5. review comment catches it sometimes
  6. AGENTS.md prose: a polite wish

Prose in a prompt is a suggestion. A failing check is a fact.

More: don't confuse guidance for guardrails

actionable errors are just in time prompts

AGENTS.mdloaded every session, all of it, relevant or not. Burns context. Easy to skim past.
an actionable errorappears only when the mistake happens, on the exact line, with the exact fix.

Don't front load the context.
Deliver it the moment it's needed.

A rule that never fires costs zero tokens. A rule that fires is the most relevant prompt the agent will see all day.

The best prompt arrives exactly when the agent is about to be wrong.

anatomy of a good rule

The error message is the prompt. The agent reads it and fixes itself.

error: banned import

😐 the agent guesses

error: `pandas` is banned.
  Use duckdb for SQL style queries
  or polars for dataframes.
  See docs/data.md

😎 the agent knows

  • says what is wrong
  • says what to do instead
  • points where to read more
  • is deterministic: same input, same answer

real rules, real cheap

Ban a library with ruff:

[tool.ruff.lint.flake8-tidy-imports.banned-api]
"pandas".msg = "Use duckdb or polars instead."
"requests".msg = "Use httpx with a timeout."

Ban a pattern with ast-grep:

id: no-print-in-lib
language: python
rule:
  pattern: print($$$ARGS)
message: Use the logger from app.log, not print().
severity: error

Most mistakes are already a rule someone wrote. Turn it on before you write your own.

quality ratchets

A ratchet only turns one way. Pick a number: lint violations, type errors, coverage. Commit it. CI fails if it gets worse and tightens it when it gets better.

lint violations
mon  412
tue  398  ✓ ratchet tightened
wed  401  ✗ CI fails: 401 > 398
thu  371  ✓ ratchet tightened

No big bang cleanup. Turn the new rule on today, freeze the existing violations, block every new one, and let the count only fall.

Every gain gets locked in. Nobody, human or agent, can quietly give it back.

Quality Ratchets are from Building AI Agent Platforms by Ben O'Mahony and Fabian Nonnenmacher (O'Reilly). See also every failure becomes a ratchet.

where rules live

Run them where the agent will trip over them fastest.

LSPdiagnostics on every save, for every agent and every editor
watch mode daemonstests and linters rerun on every change, failures handed straight back
pre commitnothing broken gets saved
CIthe backstop that never sleeps

Agent hooks tie you to one agent. LSPs and daemons live with the codebase and work for all of them, humans included.

The shorter the loop, the less the agent wanders off building on a broken idea.

overwatch

The fastest loop is the one nobody has to start. Run your tests and linters in watch mode, right beside the agent.

  • full suite runs first, so you start green
  • every save reruns what changed
  • failures go straight back to the agent, before it moves on
  • the turn can't end while the build is red
overwatch zig ✓ 4/4 steps succeeded; 48/48 tests passed
/plugin install overwatch --marketplace benomahony/overwatch

Works with Claude Code, Codex and Neovim. github.com/benomahony/overwatch

Small enough to review in a minute. Small enough to revert in a second. On main many times a day.

The only number that matters:

time to first customer feedback

Not lines of code. Not PRs merged. How fast does a real person tell you whether it's any good?

Agents made building cheap. Being wrong is still expensive. Find out sooner.

careful now

  • noisy rules are bugs. A false positive teaches agents (and humans) to add noqa everywhere.
  • prune. Hundreds of prose rules make agents follow fewer of them. Lint rules only speak when broken, so they scale. Prose doesn't.
  • escape hatches need reasons. # noqa: BLE001 retry loop logs it
  • don't make an LLM your linter. Pass or fail, every time, for free.

try it monday

  • keep a "that again?!" list for one week
  • for each entry, find an existing lint rule
  • no rule exists? write one with ast-grep or semgrep
  • run tests and lint in watch mode with overwatch
  • make CI fail on it, and ratchet the count down
  • delete the matching line from AGENTS.md 🎉
